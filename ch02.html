2.1 先说人话：程序不等于进程

🍳 生活类比
程序是一张写好的菜谱，躺在书架上，不会自己动；进程是一个厨师拿着这张菜谱，在厨房里真正开火炒菜的过程。同一张菜谱可以给三个厨师同时用（同一个程序跑出多个进程），每个厨师有自己的灶台、锅铲和进度（独立地址空间、寄存器、程序计数器）。

所以：程序是静态的指令集合，进程是程序的一次动态执行过程，有创建、运行、消亡的生命周期。

进程实体（进程映像）由三部分组成：程序段（代码）、数据段（全局变量、堆）、PCB（进程控制块，OS 用来管理它的档案）。其中 PCB 是进程存在的唯一标志——没有 PCB 就没有进程。

对比项程序进程
存在形态静态的指令与数据集合，可长期保存动态的执行过程，有生命周期
并发性本身不能并发执行多个进程可以并发
资源不占用运行资源（存在磁盘上）占用 CPU、内存、I/O 等资源
对应关系一个程序可以对应多个进程一个进程可以执行一个或多个程序（如调用库）
唯一标志文件名 / 路径PCB（进程控制块）

进程的五个特征

动态性（最基本，有生命周期）、并发性（多进程交替推进）、独立性（独立获得资源、独立调度）、异步性（以不可预知的速度推进）、结构性（程序段 + 数据段 + PCB）。

2.2 PCB 与进程状态：一张档案卡，五种人生

2.2.1 PCB 里到底存了什么

类别内容作用
标识信息PID、UID、父进程 PID唯一标识进程与所属用户
状态信息当前状态、优先级、等待事件调度与阻塞/唤醒判断
现场信息程序计数器 PC、通用寄存器、PSW、栈指针进程切换时保存/恢复现场
资源信息页表基址、打开文件表、I/O 设备、信号量定位地址空间与占用的资源
统计信息CPU 使用时间、开始时间、记账数据性能统计与调度参考
同步通信消息队列指针、信号量、互斥量进程间协作

PCB 的组织方式有两种：链接方式（同一状态的 PCB 用指针串成队列，如就绪队列、阻塞队列）和索引方式（按状态建索引表，表项指向 PCB）。408 选择题常问「PCB 是进程存在的唯一标志」「PCB 常驻内存」。

2.2.2 五状态转换图（必须默画）

创建new
就绪ready
运行running
阻塞blocked
终止terminated
转换触发事件主动/被动考点
创建 → 就绪分配资源、初始化 PCB 完成，进入就绪队列系统创建阶段尚未获得 CPU
就绪 → 运行调度程序选中它，分配 CPU被动就绪队列 → CPU
运行 → 就绪时间片用完 / 被更高优先级抢占被动常见于分时/抢占式调度
运行 → 阻塞请求 I/O、等待信号量、等待消息主动进程自己调用阻塞原语
阻塞 → 就绪I/O 完成、信号量释放、消息到达被动由中断/其他进程唤醒
运行 → 终止正常结束、异常、被杀死主动/被动释放资源、撤销 PCB
⚠️ 三个「不存在」的转换
阻塞 → 运行（必须先回就绪队列排队）、就绪 → 阻塞（没占 CPU 怎么会因 I/O 阻塞）、阻塞 → 终止（通常先唤醒再退出）。另外：运行 → 阻塞是主动的，阻塞 → 就绪是被动的，选择题最爱在这里设「主动/被动」陷阱。

有些教材还画出「七状态」：在五状态基础上增加挂起就绪和挂起阻塞，对应进程被换出到外存。挂起的原因通常是内存紧张或用户主动挂起；挂起就绪 → 就绪（被调入内存），挂起阻塞 → 阻塞（事件已发生且被调入）。408 主要以五状态为主，七状态了解即可。

2.3 进程控制：创建、终止、阻塞、唤醒、切换

进程控制由原语完成。原语是不可中断的原子操作，通常靠关中断/开中断实现。为什么必须原子？因为 PCB 队列、状态位是共享数据结构，改到一半被中断会 inconsistent。

2.3.1 进程创建

分配唯一 PID，申请一块空白 PCB。
为新进程分配资源（内存、页表、打开文件表等）。
初始化 PCB：状态设为「创建」，设置 PC 指向程序入口，初始化寄存器与优先级。
把 PCB 插入就绪队列；若资源不足，留在创建态等待。

fork() 是经典例子：子进程复制父进程的地址空间（现代 OS 用写时复制 COW 延迟复制），共享打开文件。返回值：父进程得到子进程 PID（>0），子进程得到 0，失败返回 -1。父子进程并发执行，顺序不确定。

2.3.2 进程终止

正常结束、异常结束（越界、非法指令、I/O 故障）或被外界杀死。步骤：根据 PID 找到 PCB → 读取状态 → 若有子进程则处理（级联终止或交给 init）→ 回收资源 → 撤销 PCB。注意：终止后 PCB 不一定立刻消失，父进程可能还没 wait()，形成僵尸进程。

2.3.3 阻塞与唤醒

阻塞是进程自己调用阻塞原语：保存现场 → 状态改为阻塞 → 插入对应事件的等待队列 → 转调度程序。唤醒是其他进程/中断调用唤醒原语：从等待队列摘下 → 状态改为就绪 → 插入就绪队列。阻塞和唤醒必须成对出现，且由不同进程执行。

2.3.4 进程切换：保存旧现场，恢复新现场

保存当前进程的 CPU 现场（PC、寄存器、PSW）到其 PCB。
更新当前进程的 PCB 状态，并移入相应队列（就绪/阻塞）。
从就绪队列选一个新进程，更新其 PCB 状态为运行。
恢复新进程的现场，切换页表/地址空间，跳转到它的 PC。
📌 进程切换 ≠ 模式切换
模式切换只是用户态 ↔ 内核态，当前进程还是同一个（如系统调用返回），开销小。进程切换要换 PCB、换地址空间、换页表，开销大。中断处理过程中可能只发生模式切换，不一定发生进程切换。

2.4 进程通信（IPC）：三个渠道

方式做法优点缺点 / 考点
共享存储OS 划出一块共享内存，进程直接读写；需用 PV/管程互斥速度快，数据量大共享区的互斥同步要程序员自己保证；分为低级（基于物理地址）与高级（基于逻辑地址/文件映射）
消息传递以消息为单位，通过发送/接收原语交换；可直接（指名 PID）或间接（信箱/消息队列）无需共享地址空间，适合分布式消息拷贝有开销；消息队列有容量限制
管道一个固定大小的环形缓冲区，写进程写入、读进程读出简单，适合父子/兄弟进程半双工；写满则写阻塞，读空则读阻塞；双方必须都存在
🥤 生活类比
共享存储像合租厨房：大家都能进去用，但得约定谁先用灶台；消息传递像发快递：东西打包好，填地址，对方签收；管道像传送带：一头放、一头取，带宽固定，放满了就停。

2.5 线程：进程里的「轻量级分身」

引入线程是为了减少并发执行的开销：同一进程内的多个线程共享地址空间和资源，切换时不用换页表，开销远小于进程切换；线程也能更好地利用多核。

线程私有

线程 ID、程序计数器、寄存器组、栈、线程状态、优先级、局部变量。

这些是「每个线程各干各的」所必需的现场。

线程共享（同进程内）

地址空间、代码段、数据段、堆、打开文件表、信号处理函数、当前工作目录。

共享带来效率，也带来数据竞争，需要同步。

用户级线程 vs 内核级线程

用户级线程（ULT）内核级线程（KLT）
管理者用户态线程库，内核不知道线程存在内核直接管理、调度
切换用户态完成，开销小需进入内核，开销较大
阻塞影响一个线程阻塞，整个进程阻塞一个线程阻塞，其他线程可继续
多核不能真正并行可分配到多个核

多线程模型：多对一（多个 ULT 映射到一个 KLT，效率高但一个阻塞全阻塞、不能多核）、一对一（每个 ULT 一个 KLT，并发好但开销大）、多对多（m 个 ULT 映射到 n 个 KLT，兼顾两者，实现复杂）。

2.6 处理机调度：谁先上 CPU

2.6.1 三级调度与调度时机

高级调度（作业调度）

从外存后备队列选作业调入内存，创建进程。频率最低。

中级调度（内存调度）

把暂时不能运行的进程换出到外存（挂起），或把挂起进程换回内存。目的是提高内存利用率。

低级调度（进程调度）

从就绪队列选进程分配 CPU。频率最高，是本章核心。

调度时机：进程创建、终止、阻塞、I/O 完成、时间片用完、更高优先级进程到达（抢占式）。不能调度的情况：中断处理过程中（通常）、内核临界区中（视 OS 设计）。

调度方式：非抢占式（进程主动放弃 CPU 才切换，简单、开销小、实时性差）与抢占式（更高优先级/时间片到就强制切换，响应好、开销大、需保护现场）。

2.6.2 调度指标（公式必须背）

基础公式 周转时间 = 完成时间 − 到达时间
带权周转时间 = 周转时间 ÷ 服务时间（≥ 1）
等待时间 = 周转时间 − 服务时间（不考虑 I/O 时）
响应时间 = 首次获得 CPU 的时间 − 提交时间

平均周转时间、平均带权周转时间都是把每个进程的值求平均。注意：带权周转时间对短作业更敏感，是衡量「短作业是否被善待」的重要指标。

2.6.3 七大调度算法

算法规则抢占优点缺点 / 考点
FCFS 先来先服务按到达顺序排队非抢占公平、简单短作业排队久（护航效应），平均周转不一定好
SJF/SPF 短作业优先每次选服务时间最短的非抢占平均等待/周转时间最短（理想）需预知运行时间；长作业可能饥饿
SRTN 最短剩余时间优先SJF 的抢占版，新短作业可抢占抢占平均周转更优抢占开销；长作业饥饿
HRRN 高响应比优先响应比 = (等待 + 服务) / 服务非抢占兼顾短作业与等待久的长作业，避免饥饿每次调度要计算响应比
优先级选优先级最高的可抢占/非抢占可区分紧急程度低优先级饥饿；可用「老化」缓解
RR 时间片轮转就绪队列轮流执行一个时间片抢占（时间片到）响应快、公平，适合分时时间片过大→退化为 FCFS；过小→切换开销大
多级反馈队列多级队列，优先级递减、时间片递增；新进程进最高级，用完时间片降级抢占兼顾短作业、交互性与长作业，通用性强实现复杂；低优先级可能饥饿
📌 例题：SJF 非抢占（手算一遍）
进程：P1(到达 0, 服务 7)、P2(2, 4)、P3(4, 1)、P4(5, 4)。
调度顺序：P1 0~7 → P3 7~8（此时 P2、P3、P4 都已到达，选最短的 P3）→ P2 8~12 → P4 12~16。
完成时间：P1=7、P2=12、P3=8、P4=16；周转：7、10、4、11；带权：1、2.5、4、2.75。
平均周转 = (7+10+4+11)/4 = 8；平均带权 = (1+2.5+4+2.75)/4 = 2.5625。

2.6.4 实时调度

EDF（最早截止期优先）：动态优先级，截止期越早优先级越高，可抢占，理论上 CPU 利用率可达 100%。RMS（速率单调调度）：静态优先级，周期越短优先级越高，适合周期性硬实时任务，CPU 利用率有上限（n 个任务时约 n(2^(1/n)−1)）。

2.7 同步与互斥：并发带来的麻烦

🚻 生活类比
厕所只有一个隔间（临界资源），多个人（进程）都要用。如果两个人同时进去，就出乱子——这就是互斥。而「你先洗完我再用」是同步：不是抢，而是有先后依赖。同步是直接制约（合作），互斥是间接制约（争资源）。

临界区是进程中访问临界资源的那段代码。互斥访问的四条原则（背）：

空闲让进

临界区空着，就允许一个进程进入。

忙则等待

已有进程在临界区，其他进程必须等。

有限等待

等待的进程不能无限期等下去。

让权等待

进不去就释放 CPU，不要忙等（理想）。

2.7.1 软件方法（四个经典，考试爱考缺陷）

方法核心代码问题
单标志法while(turn != i); 临界区; turn = j;强制轮流，违反「空闲让进」
双标志先检查while(flag[j]); flag[i]=true;检查与置位之间可能被切换，两个进程同时进入，违反「忙则等待」
双标志后检查flag[i]=true; while(flag[j]);都先举手再等，可能互相等待，违反「空闲让进」/有限等待
Petersonflag[i]=true; turn=j; while(flag[j] && turn==j);满足互斥、空闲让进、有限等待；仍忙等，不满足「让权等待」

2.7.2 硬件方法

中断屏蔽：关中断后临界区不会被打断，简单但只适合单 CPU，且用户态无权关中断。TestAndSet（TS）：原子地读出并置 true，返回旧值；Swap：原子交换两个变量的值。二者都满足互斥，但都是忙等，不满足让权等待，且可能饥饿。

2.8 信号量与 PV 操作：408 大题的半壁江山

信号量是一个整型变量，只能通过 P（wait） 和 V（signal） 两个原语访问。P 表示申请资源，V 表示释放资源。

// 记录型信号量
typedef struct {
    int value;          // 剩余资源数（可为负）
    struct process *L;  // 等待队列
} semaphore;

void P(semaphore S) {   // wait：申请
    S.value--;
    if (S.value < 0) {
        // 资源不够，把当前进程加入 S.L，阻塞
        block(S.L);
    }
}
void V(semaphore S) {   // signal：释放
    S.value++;
    if (S.value <= 0) {
        // 还有进程在等，唤醒一个
        wakeup(S.L);
    }
}
📌 value 的含义（选择题必考）
S.value > 0：还有这么多可用资源。
S.value = 0：资源刚好用完，没有进程等待。
S.value < 0：没有资源了，且 |S.value| 个进程正在等待。
例：初值 3，当前 −2，说明资源已耗尽且 2 个进程在等待。

2.8.1 用信号量实现互斥

semaphore mutex = 1;   // 互斥信号量初值为 1
P(mutex);
// 临界区
V(mutex);

2.8.2 用信号量实现同步（前趋关系）

若 A 必须在 B 之前执行：设 S = 0；A 执行完 V(S)，B 开始前 P(S)。这样 B 会一直等到 A 发出信号。

2.8.3 生产者-消费者（必须会默写）

semaphore empty = n;   // 空缓冲区数量
semaphore full  = 0;   // 满缓冲区数量
semaphore mutex = 1;   // 缓冲区互斥

Producer:
    while (true) {
        produce(item);
        P(empty);        // ① 先申请空位
        P(mutex);        // ② 再进临界区
        put(item);
        V(mutex);        // ③ 退出临界区
        V(full);         // ④ 通知消费者
    }

Consumer:
    while (true) {
        P(full);         // ① 先申请数据
        P(mutex);        // ② 再进临界区
        item = get();
        V(mutex);        // ③ 退出临界区
        V(empty);        // ④ 通知生产者
        consume(item);
    }
⚠️ 为什么不能先 P(mutex) 再 P(empty)？
如果生产者先拿到 mutex，再发现 empty=0 而被阻塞，此时 mutex 还在它手里；消费者想来取数据时被 mutex 挡在门外，无法执行 V(empty) 唤醒生产者——互相等待，死锁。
口诀：先资源信号量，后互斥信号量；P 的顺序不能反，V 的顺序无所谓。

2.8.4 读者-写者（读者优先版）

int count = 0;          // 当前读者数
semaphore mutex = 1;    // 保护 count
semaphore rw = 1;       // 读写互斥

Reader:
    P(mutex);
    if (count == 0) P(rw);   // 第一个读者锁住写者
    count++;
    V(mutex);
    read();
    P(mutex);
    count--;
    if (count == 0) V(rw);   // 最后一个读者放行写者
    V(mutex);

Writer:
    P(rw);
    write();
    V(rw);

这个版本是读者优先：只要不断有读者到来，写者可能一直等（写者饥饿）。若改为写者优先，需要额外的信号量阻止新读者在写者等待时进入。

2.9 管程：把同步封装起来

管程（Monitor）把共享数据和对它的操作封装在一起，同一时刻只允许一个进程在管程内执行——互斥由编译器/语言机制保证，程序员不用手写 P/V。管程内用条件变量实现等待：wait 让进程在条件变量上等待并释放管程；signal 唤醒一个等待者。

对比信号量管程
本质一个整型变量 + 等待队列，P/V 显式调用语言级封装，互斥自动保证
互斥程序员负责编译器/运行时负责
条件变量无有，wait/signal 没有记忆：signal 时无人等待则丢失
典型OS 内核、PV 大题Java synchronized + wait/notify、C# lock

2.10 死锁：四个条件、四种对策

死锁是多个进程因竞争资源而互相等待，若无外力介入都无法推进。与饥饿的区别：死锁是「循环等待，永远解不开」；饥饿是「长期得不到资源，但理论上还能等到」。

2.10.1 四个必要条件（缺一不可）

互斥

资源一次只能被一个进程占用。

不可剥夺

已获得的资源不能被强行抢走。

请求并保持

占着已有资源，又去申请新资源。

循环等待

存在进程—资源的环形等待链。

2.10.2 四种对策

策略做法代价 / 考点
预防破坏四个条件之一：一次性分配所有资源（破坏请求并保持）、可剥夺、按序分配资源（破坏循环等待）资源利用率低、可能饥饿；按序分配最常用
避免银行家算法：每次分配前判断是否仍存在安全序列需预知最大需求；计算开销大；安全 ≠ 不死锁，但不安全一定可能死锁
检测资源分配图化简；死锁定理：图不可完全化简则有死锁单实例资源图中「有环」是死锁的充要条件；多实例有环不一定死锁
解除资源剥夺、撤销进程、进程回退选择牺牲者；回退需要检查点

2.10.3 银行家算法（手算模板）

数据结构：Available（可用资源）、Max（最大需求）、Allocation（已分配）、Need = Max − Allocation。安全性算法：Work = Available；反复找 Need[i] ≤ Work 的进程，令 Work += Allocation[i]，标记完成；若所有进程都能完成，则安全。

📌 经典例题（5 进程 3 类资源）
Available = (3, 3, 2)。各进程 Need：P0(7,4,3)、P1(1,2,2)、P2(6,0,0)、P3(0,1,1)、P4(4,3,1)。
Work=(3,3,2) → P1 Need(1,2,2) 可满足，完成后 Work=(5,3,2) → P3(0,1,1) 完成，Work=(7,4,3) → P4(4,3,1) 完成，Work=(7,4,5) → P0(7,4,3) 完成，Work=(7,5,5) → P2(6,0,0) 完成。
安全序列：P1 → P3 → P4 → P0 → P2（答案不唯一）。

请求资源时：① 检查 Request ≤ Need；② 检查 Request ≤ Available；③ 试探性分配（Available −= Request，Allocation += Request，Need −= Request）；④ 跑安全性算法；安全则正式分配，不安全则回滚并让进程等待。

🚀 进阶深挖（教材级）

以下内容对齐王道《操作系统考研复习指导》与汤小丹教材的处理深度，二轮复习必看。

深挖 1 · 进程切换到底贵在哪

进程切换要保存/恢复寄存器与 PC、切换页表基址（CR3）、刷新 TLB（或加 ASID 避免全刷）、切换内核栈、更新调度数据结构。TLB 失效会让后续访存变慢，所以「进程切换开销」远大于「线程切换」。线程切换只需换寄存器与栈，不换地址空间。408 选择题常问「哪些操作会增大切换开销」。

深挖 2 · 调度算法的选择不是背出来的

批处理系统追求吞吐量，常用 FCFS、SJF、HRRN；分时系统追求响应，常用 RR、多级反馈队列；实时系统追求截止时间，常用 EDF、RMS。题目给场景，先问三个问题：是否允许抢占？是否知道运行时间？更在意响应还是吞吐？答案自然出来。

深挖 3 · PV 大题的固定套路

找角色。把题目里的「谁」列成进程：生产者/消费者、读者/写者、司机/售票员、爸爸/儿子/女儿。
找资源与约束。缓冲区容量、互斥访问的共享变量、谁必须先于谁（前趋关系）。
设信号量。资源信号量初值 = 可用数量；互斥信号量初值 = 1；同步信号量初值 = 0。
写代码并检查。每个 P 都有对应的 V；资源 P 在互斥 P 之前；不会出现「持有 mutex 等资源」的死锁。

深挖 4 · 死锁检测：资源分配图怎么化简

圆圈是进程，方框是资源，方框内圆点表示实例数。进程 → 资源是请求边，资源 → 进程是分配边。化简：找一个「请求都能被满足」的进程，消去它的所有边，释放资源；重复。若最终所有边都能消去，则无死锁；否则有死锁。单实例图中「有环」等价于死锁；多实例图有环只是可能死锁，必须化简判断。

🌐 多源视角（不同教材的讲法）
  • 【汤小丹】进程 = 程序 + 数据 + PCB：强调「进程实体」概念，PCB 是 OS 感知进程存在的唯一依据。本站的五状态图按此体系绘制。
  • 【王道】调度算法用「到达—服务」表推进：做题时画时间轴，每一步只问「此刻谁已到达、谁最短/优先级最高」，比背结论稳。
  • 【OSTEP】进程就是「正在运行的程序」+ 机器状态：把进程抽象为「PC、寄存器、地址空间」三件套，和 408 的 PCB 现场信息完全对应。
  • 【Linux】线程就是共享地址空间的进程（task）：Linux 不区分进程/线程，统一用 task_struct，靠 clone 的共享标志决定共享哪些资源。可作为「线程共享/私有」的实例记忆。

⚠️ 本章避坑清单

PCB 是进程存在的唯一标志；程序不是进程，程序段也不是 PCB。
运行→阻塞是主动，阻塞→就绪是被动；阻塞不能直接到运行。
进程切换 ≠ 模式切换；系统调用返回可能只发生模式切换。
用户级线程一个阻塞全进程阻塞，不能利用多核；内核级线程才可以。
SJF 平均周转最短，但可能饿死长作业；HRRN 用响应比缓解饥饿。
PV 里「先 P 资源，后 P 互斥」；反过来会死锁。
S.value < 0 时，绝对值才是等待进程数，不是资源数。
银行家算法「安全」只是「存在安全序列」，不是「一定不死锁」；不安全状态一定可能死锁。
单实例资源分配图有环 ⇔ 死锁；多实例有环不一定。

📝 章内练习（16 题 · 基础 → 提高 → 真题改编）

🟢 第一档 · 基础（4 题）

基础练习 1 · 考点：进程与程序
下列关于进程与程序的叙述，正确的是：
A. 进程是静态的，程序是动态的
B. 一个程序只能对应一个进程
C. 进程是程序的一次执行过程，有生命周期
D. 程序的存在标志是 PCB
解析：选 C。程序是静态指令集合，进程是动态执行过程，有创建、运行、消亡。同一个程序可以对应多个进程（如开多个浏览器窗口）；PCB 是进程存在的唯一标志，不是程序的。
基础练习 2 · 考点：PCB
操作系统感知进程存在的唯一标志是：
A. 程序段
B. PCB
C. 数据段
D. 进程的优先级
解析：选 B。PCB 记录进程标识、状态、现场、资源等信息，OS 通过 PCB 管理和调度进程；进程被撤销时 PCB 也被回收。程序段和数据段只是进程实体的一部分，不能作为存在标志。
基础练习 3 · 考点：状态转换
下列进程状态转换中，不可能直接发生的是：
A. 运行 → 阻塞
B. 运行 → 就绪
C. 阻塞 → 就绪
D. 阻塞 → 运行
解析：选 D。阻塞进程被唤醒后先进入就绪队列，必须再被调度才能运行，不能直接跳到运行。A 是进程主动等待 I/O；B 是时间片到/被抢占；C 是 I/O 完成或信号量释放。
基础练习 4 · 考点：线程共享资源
同一进程内的多个线程，通常不共享的是：
A. 栈和寄存器
B. 代码段
C. 全局变量
D. 打开文件表
解析：选 A。线程私有：线程 ID、PC、寄存器组、栈、局部变量、状态。共享：地址空间、代码段、数据段/全局变量、堆、打开文件表。栈必须私有，否则函数调用与局部变量会互相踩踏。

🟡 第二档 · 提高（4 题）

提高练习 5 · 考点：进程切换
进程切换过程中，通常不需要做的是：
A. 保存当前进程的 PC 和寄存器
B. 更新 PCB 状态并移入相应队列
C. 把当前进程的程序代码复制到新进程
D. 恢复新进程的现场并切换页表
解析：选 C。进程切换是「换执行现场」，不是复制代码；代码段可以共享或本来就在各自地址空间。A、B、D 都是标准步骤，D 中切换页表/地址空间是进程切换比线程切换贵的关键。
提高练习 6 · 考点：用户级线程
用户级线程的主要缺点是：
A. 线程切换必须进入内核，开销大
B. 一个线程阻塞会导致整个进程阻塞，且不能利用多核并行
C. 无法在同一进程内共享地址空间
D. 必须一对一映射到内核线程
解析：选 B。用户级线程由用户态库管理，内核只看到一个进程；某个线程发起阻塞系统调用，内核会阻塞整个进程，其他线程也跑不了；内核也不知道多线程存在，无法分配到多核。A 是内核级线程的缺点；C、D 与事实相反。
提高练习 7 · 考点：SJF 计算
三个进程：P1(到达 0，服务 5)、P2(到达 1，服务 2)、P3(到达 2，服务 1)。采用非抢占式 SJF，平均周转时间是：
A. 4.00
B. 5.33
C. 6.00
D. 8.00
解析：选 B。0 时刻只有 P1，先运行 P1 到 5；此时 P2、P3 都已到达，选最短的 P3（1）运行 5~6；再运行 P2 6~8。完成时间：P1=5、P2=8、P3=6；周转：5、7、4；平均 = (5+7+4)/3 = 16/3 ≈ 5.33。对应等待时间：0、5、3。
提高练习 8 · 考点：RR 计算
三个进程：P1(到达 0，服务 5)、P2(到达 1，服务 2)、P3(到达 2，服务 1)。采用时间片 q=2 的轮转调度，平均周转时间是：
A. 3.67
B. 4.33
C. 4.67
D. 5.33
解析：选 C。时间轴：P1 0~2（剩 3）；P2 2~4 完成；P3 4~5 完成；P1 5~7（剩 1）；P1 7~8 完成。完成时间：P1=8、P2=4、P3=5；周转：8、3、3；平均 = 14/3 ≈ 4.67。RR 的响应好，但周转不一定优于 SJF。

🔴 第三档 · 真题改编（8 题 · 题型对标）

真题改编2014 题型练习 9 · 考点：临界区四原则
下列原则中，不属于临界区互斥访问四条原则的是：
A. 空闲让进
B. 忙则等待
C. 有限等待
D. 优先级高者先进入临界区
解析：选 D。四条原则是空闲让进、忙则等待、有限等待、让权等待。优先级是调度策略，不是临界区互斥的必要条件；如果按优先级插队，反而可能破坏有限等待。
真题改编2016 题型练习 10 · 考点：Peterson 算法
Peterson 算法满足的互斥原则是：
A. 互斥、空闲让进、有限等待，但不满足让权等待
B. 只满足互斥，其他都不满足
C. 同时满足四条，包括让权等待
D. 不满足互斥，只满足有限等待
解析：选 A。Peterson 用「flag 举手 + turn 让位」保证互斥、空闲让进、有限等待；但进不去时仍在 while 自旋，占用 CPU，属于忙等，不满足让权等待。这是软件方法的通病。
真题改编2011 题型练习 11 · 考点：信号量 value
某记录型信号量 S 的初值为 3。经过若干次 P、V 操作后，S.value = −2，这意味着：
A. 还有 2 个资源可用
B. 资源已用完，有 2 个进程在等待
C. 有 2 个进程正在使用资源
D. 信号量出错，value 不能为负
解析：选 B。记录型信号量的 value 可以为负：负值的绝对值 = 等待队列中的进程数。value=−2 说明 3 个资源早已分完，还有 2 个进程因申请不到而阻塞。若为整型信号量（不记录等待队列），才会出现「一直减」的忙等，但题目明确是记录型。
真题改编2019 题型练习 12 · 考点：生产者-消费者 P 顺序
在生产者-消费者问题中，生产者执行 P(empty) 与 P(mutex) 的顺序必须是：
A. 先 P(mutex)，再 P(empty)
B. 顺序任意，不影响结果
C. 先 P(empty)，再 P(mutex)
D. 两个 P 必须合并成一个原子操作
解析：选 C。若先 P(mutex) 再 P(empty)，当缓冲区满时生产者持有 mutex 阻塞，消费者无法进入临界区执行 V(empty)，双方互相等待——死锁。口诀：先资源，后互斥。V 的顺序通常不影响正确性。
真题改编2013 题型练习 13 · 考点：读者-写者
读者优先的读者-写者模型中，可能发生的是：
A. 两个写者同时写文件
B. 读者与写者同时访问文件
C. 读者被写者永久阻塞
D. 写者长期得不到机会（写者饥饿）
解析：选 D。读者优先版本中，只要还有读者在或不断有新读者到来，rw 就不会释放，写者可能一直等。A、B 被 rw 互斥排除；C 与「读者优先」相反。
真题改编2015 题型练习 14 · 考点：死锁必要条件
下列各项中，不属于死锁必要条件的是：
A. 进程优先级相同
B. 互斥条件
C. 请求并保持条件
D. 循环等待条件
解析：选 A。死锁四个必要条件：互斥、不可剥夺、请求并保持、循环等待。优先级相同既不是必要条件，也不是充分条件；优先级不同的进程同样可能死锁。
真题改编2018 题型练习 15 · 考点：银行家算法安全序列
系统有 3 类资源，Available=(1,1,1)。三个进程的 Allocation / Need 分别为：P1(1,0,0)/(1,0,0)，P2(0,1,0)/(2,1,0)，P3(0,0,1)/(0,0,1)。下列哪个是安全序列？
A. P1 → P2 → P3
B. P2 → P1 → P3
C. P3 → P2 → P1
D. 不存在安全序列
解析：选 A。Work=(1,1,1)：P1 Need(1,0,0) 满足，完成后 Work=(2,1,1)；P2 Need(2,1,0) 满足，完成后 Work=(2,2,1)；P3 Need(0,0,1) 满足，全部完成。B 中 P2 初始 Need 第一类为 2 > 1，不能先做；C 中 P3 先做后 Work=(1,1,2)，P2 仍缺第一类 1，不能接着做；D 错，安全序列存在。
真题改编2021 题型练习 16 · 考点：多级反馈队列
多级反馈队列调度算法中，新创建的进程通常：
A. 直接进入优先级最低的队列
B. 进入时间片最长的队列
C. 进入优先级最高、时间片最短的队列
D. 随机选择一个队列
解析：选 C。多级反馈队列让新进程先到最高优先级、最短时间片的队列，短作业/交互型进程能快速完成；用完时间片还没完就降到下一级（时间片变长），长作业逐步下沉，兼顾吞吐与响应。低优先级队列可能饥饿，需老化。
