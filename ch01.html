1.1 先说人话：操作系统是什么

🏨 生活类比
把计算机想成一家酒店：CPU 是厨师，内存是操作台，硬盘是仓库，打印机/网卡是前台设备，顾客是用户程序。如果每个顾客都直接冲进厨房抢锅、翻仓库，场面必然失控。操作系统就是酒店经理：它不替顾客炒菜，但负责排班、分配操作台、登记仓库钥匙、安排设备使用顺序，并规定「顾客只能通过前台提需求」。

所以 OS 不是「一个具体的程序」，而是一组管理资源、提供服务、控制程序执行的系统软件。

教材定义：操作系统（Operating System，OS）是指控制和管理整个计算机系统的硬件与软件资源，合理地组织、调度计算机的工作与资源的分配，进而为用户和其他软件提供方便接口与环境的程序集合。它是计算机系统中最基本的系统软件。

三层视角，一句话记住

资源管理者

管理处理机、存储器、文件、I/O 设备。对应后面四章：进程管理、内存管理、文件管理、I/O 管理。

用户接口

命令接口（命令行）、程序接口（系统调用）、图形用户界面（GUI）。用户程序不能直接碰硬件，只能请求 OS。

扩充机器

裸机只认二进制和寄存器；OS 在上面铺了一层抽象，让用户看到「文件、进程、虚拟内存」这些好用的东西。

📌 408 高频：OS 的「两个最基本特征」
408 教材普遍把 并发 和 共享 视为操作系统最基本的两个特征，二者互为存在条件：没有并发，共享没有意义；没有共享，并发无法实现。选择题常把「并发」偷换成「并行」来设错。

1.2 四大特征：并发、共享、虚拟、异步

特征含义生活类比易错点
并发两个或多个事件在同一时间间隔内发生。单核 CPU 上多个程序交替执行，宏观同时、微观串行。一个人同时炒两道菜：这盘翻两下，那盘翻两下并发 ≠ 并行。并行是同一时刻真正同时执行，需要多核/多处理机。
共享系统中的资源可供内存中多个并发执行的进程共同使用。分互斥共享（打印机）和同时共享（磁盘文件、可重入代码）。打印机一次只能一个人用；图书馆的书可以多人同时看互斥共享的资源叫临界资源，必须互斥访问。
虚拟把一个物理实体变成多个逻辑对应物。分时分复用（CPU 分时）和空分复用（虚拟内存）。一个厨师被顾客看成「同时有好几个厨师」虚拟是逻辑上的，不增加真实硬件。
异步多道程序环境下，进程以不可预知的速度向前推进，走走停停。炒菜时接电话，回来接着炒，节奏被打乱异步性带来结果的不确定性，所以需要同步机制。
⚠️ 并发与并行，选择题年年换皮
并发：同一时间间隔内，宏观上同时发生（单核也能并发）。
并行：同一时刻，真正同时发生（必须多核或多处理机）。
经典判断：单处理机系统中，CPU 计算与 I/O 传输可以并行（不同硬件各干各的）；两个进程在同一 CPU 上只能并发，不能并行。

1.3 OS 的功能：四管理 + 两接口

处理机管理。进程控制、进程同步、进程通信、死锁处理、处理机调度。目标：让 CPU 忙而有序。→ 第 2 章。
存储器管理。内存分配与回收、地址映射、内存保护与共享、内存扩充（虚拟内存）。→ 第 3 章。
文件管理。文件存储空间管理、目录管理、文件读写与保护。→ 第 4 章。
设备管理。缓冲管理、设备分配、设备处理、虚拟设备。→ 第 5 章。
用户接口。命令接口（联机/脱机命令）、程序接口（系统调用）、GUI。
扩充机器。把裸机改造成功能更强、使用更方便的「虚拟机器」。

命令接口 vs 程序接口

命令接口给人在终端里用：联机命令接口（交互式，你一句它一句，如 shell）和脱机命令接口（批处理，一次写一批作业命令）。程序接口给程序用，核心就是系统调用：程序员通过库函数或直接陷入指令，请求 OS 提供内核级服务。

1.4 发展与分类：从手工到实时

阶段核心做法优点缺点 / 考点
手工操作用户独占全机，人工装纸带/卡片无人机矛盾突出，CPU 大量空闲
单道批处理内存中只放一道作业，监控程序自动依次运行减少人工干预，CPU 利用率略升CPU 与 I/O 串行，内存浪费，仍无交互
多道批处理内存放多道作业，CPU 与 I/O 重叠，作业调度选下一道资源利用率高、吞吐量大无交互、作业周转长；需要中断、通道、作业调度
分时系统时间片轮转，多用户通过终端同时使用交互性好、多路性、独立性、及时性时间片过小切换开销大，过大响应变差
实时系统按截止时间处理外部事件，分硬实时/软实时及时、可靠、专用硬实时错过截止时间后果严重；不追求吞吐量
网络/分布式/个人/嵌入式联网共享、多机协同、面向个人/专用设备各有所长分布式强调透明性与自治性；嵌入式强调裁剪与实时
📌 多道批处理为什么能提高利用率？
当一道程序因 I/O 而阻塞时，CPU 立刻切换去执行另一道程序，让 CPU 与 I/O 设备重叠工作。注意：多道程序的道数不是越多越好——内存装不下会频繁换入换出，反而抖动。多道批处理是「并发」概念真正落地的地方，也带来了同步、死锁、保护等新问题。

分时系统的四个特点（背）

多路性（多个终端同时连）、独立性（用户彼此感觉独占）、及时性（较短时间得到响应）、交互性（人机对话）。实时系统的关键词则是及时性 + 可靠性 + 截止时间，硬实时必须严格满足，软实时可以偶尔超时。

1.5 运行环境：用户态、内核态、中断、系统调用

这是本章最核心、也是选择题最爱考的一节。先记住一条主线：用户程序没有权限直接操作硬件，必须通过「陷入」进入内核，由内核代为完成。

1.5.1 两种状态与特权指令

用户态（目态）

用户程序运行的状态，只能执行非特权指令，访问受限的内存区域。想做危险操作，只能请求 OS。

例：算术运算、逻辑运算、取数、跳转、访存（受界地址检查）。

内核态（管态 / 核心态）

OS 内核运行的状态，可以执行特权指令，访问全部硬件与内存。用户态到内核态的切换由硬件中断/异常机制完成。

例：关中断/开中断、置时钟、修改 PSW、切换页表、加载页表基址、I/O 指令、停机。

⚠️ 状态切换的方向不能反
用户态 → 内核态：只能通过中断、异常、系统调用（执行陷入指令 trap）这些「入口」，由硬件完成状态切换。用户程序不能自己写一句「我要进内核」。
内核态 → 用户态：由 OS 执行一条特权指令修改程序状态字（PSW），主动返回用户态。
陷阱题：「用户态程序可以通过修改 PSW 进入内核态」——错，修改 PSW 本身就是特权指令，用户态执行会触发异常。

1.5.2 中断与异常：OS 的「门铃」

类别来源典型例子特点
外中断（中断）CPU 外部I/O 完成、时钟中断、键盘输入、网络包到达与当前指令无关，异步；分可屏蔽/不可屏蔽
内中断（异常）CPU 内部，当前指令执行引起缺页、除零、非法操作码、地址越界、系统调用（陷入）同步；又分故障 fault、自陷 trap、终止 abort

异常再细分：故障（fault）——如缺页，处理后可以重新执行出错指令；自陷（trap）——如系统调用、断点，是程序主动安排的；终止（abort）——如硬件故障、严重非法指令，无法恢复，只能终止进程。

📌 中断处理的标准流程（会排序）
① 关中断（防止现场被破坏）→ ② 保存断点（PC、PSW）→ ③ 识别中断源（查中断向量表）→ ④ 保存现场（通用寄存器等）→ ⑤ 执行中断服务程序 → ⑥ 恢复现场 → ⑦ 开中断并返回。
注意：保存断点和保存现场不是一回事；断点由硬件保存，现场通常由中断服务程序保存。中断向量表存的是中断服务程序的入口地址。

1.5.3 系统调用：用户程序求内核办事的唯一正规渠道

系统调用是 OS 提供给应用程序的程序接口，运行在内核态。用户程序执行一条陷入指令（trap / 访管指令），CPU 切换到内核态，按系统调用号查表，执行对应的内核服务，完成后返回用户态。

传参。把系统调用号与参数放入寄存器、栈或内存块（参数块地址放寄存器）。
陷入。执行 trap 指令，硬件保存返回地址与 PSW，切换到内核态。
查表。内核根据系统调用号在系统调用表中找到服务程序入口。
执行。内核完成实际工作（如读文件、创建进程、分配内存），可能阻塞调用者。
返回。恢复现场，把返回值放入寄存器，切回用户态继续执行。
🔍 系统调用 vs 库函数
系统调用是内核提供的服务，执行时必然发生用户态→内核态切换，开销较大。库函数是用户态程序（如 C 标准库），本身不一定进内核；很多库函数只是对系统调用的封装（如 printf 最终可能调用 write）。
所以：「库函数都在内核态执行」错；「系统调用一定涉及状态切换」对。

1.6 内核结构：大内核、微内核、分层、模块化

结构做法优点缺点
大内核（单体内核）进程管理、内存管理、文件系统、设备驱动等全部放在内核态，模块间直接函数调用性能高，调用开销小内核庞大、耦合重，可靠性与可维护性差，一处崩溃可能拖垮全系统
微内核内核只保留进程调度、中断处理、进程通信、基本内存管理；文件系统、驱动、网络等作为用户态服务可靠、可扩展、可移植、易维护；服务崩溃不影响内核频繁的用户态/内核态切换与消息传递，性能开销大
分层结构按层次组织，每层只依赖下一层结构清晰、易调试层次划分困难，跨层调用效率低
模块化内核由可动态加载的模块组成灵活、易扩展模块间接口与依赖需严格管理
外核内核只负责资源分配与保护，把硬件操作交给用户态库减少抽象开销，灵活用户库复杂，保护与复用难度高
📌 微内核的「性能差」到底差在哪？
用户程序要读文件：微内核中要「用户态 → 内核态（消息）→ 文件服务（用户态）→ 内核态 → 用户态」，多次切换 + 消息拷贝；大内核一次系统调用直接进内核完成。所以微内核是用性能换可靠性与可扩展性。

1.7 OS 的引导与虚拟机

1.7.1 从按下电源到 OS 跑起来

加电自检（POST）。CPU 从固定地址取指，执行 BIOS/UEFI 中的固件，检测内存、显卡、键盘等硬件。
读主引导记录（MBR）。BIOS 把磁盘 0 号扇区（512B）读入内存。MBR 含引导代码、分区表和结束标志 55AA。
找活动分区。引导代码扫描分区表，找到活动分区，读取其引导记录（分区引导程序）。
加载 OS 内核。引导程序把内核映像装入内存，把控制权交给内核入口，内核初始化后就绪队列、内存管理、设备驱动等。
启动第一个进程。内核创建 0 号/1 号进程（或 init/systemd），再由它拉起用户态服务与登录界面。
📌 408 常考：MBR 里有什么？
MBR 位于磁盘0 号扇区，共 512 字节：引导代码（约 446B）+ 分区表（64B，每项 16B，最多 4 个主分区）+ 结束标志 55AA（2B）。它不属于任何一个分区，先于 OS 运行。

1.7.2 虚拟机

虚拟机（VM）用软件模拟一台完整计算机，让多个 OS 在同一物理机上隔离运行。核心是虚拟机监视器（VMM / Hypervisor）。

第一类 VMM（Type-1）

直接运行在硬件上，如 VMware ESXi、Xen、KVM（内核态）。性能好，常用于服务器/云。

第二类 VMM（Type-2）

运行在宿主 OS 之上，如 VirtualBox、VMware Workstation。安装方便，性能多一层开销。

虚拟机需要解决「客户 OS 也以为自己在内核态」的问题，常见做法是特权级压缩：把客户 OS 的内核态降级到用户态，遇到特权指令就陷入 VMM，由 VMM 模拟执行。

🚀 进阶深挖（教材级）

以下内容对齐汤小丹《计算机操作系统》与王道《操作系统考研复习指导》的处理深度，零基础可先跳过，二轮复习必看。

深挖 1 · 程序从源码到运行：编译、链接、装入

源程序先经编译生成目标模块，再由链接程序把多个目标模块与库函数链接成可执行文件，最后由装入程序装入内存执行。链接分三种：

方式做法特点
静态链接运行前把所有目标模块和库函数拼成一个完整可执行文件运行快，但文件大、库更新需重新链接
装入时动态链接装入内存时边装入边链接便于模块共享与更新，实现较复杂
运行时动态链接程序执行到某个模块时才链接按需链接，节省内存，支持动态库

装入也分三种：绝对装入（编译时已知物理地址，只适合单道）、可重定位装入/静态重定位（装入时一次性修改地址，运行中不能移动）、动态运行时装入/动态重定位（运行时由重定位寄存器把逻辑地址转成物理地址，支持内存紧凑与虚拟内存）。

深挖 2 · 为什么系统调用开销大？

一次系统调用至少涉及：保存用户现场、切换栈与 PSW、查系统调用表、内核态执行、恢复现场、返回用户态。若涉及 I/O，还可能阻塞并触发调度。高频系统调用（如逐字节 read）会把大量时间花在切换上，所以要用缓冲、批量读写、mmap 等手段减少调用次数。这也是「微内核性能差」的根本原因。

深挖 3 · 中断与异常的判定表（做题直接套）

事件类别是否切换内核态处理完返回哪里
键盘输入、网卡收包外中断是被中断指令的下一条
时钟中断外中断是被中断指令的下一条（可能触发调度）
缺页异常内中断 · 故障是重新执行引发缺页的指令
系统调用内中断 · 自陷是陷入指令的下一条
整数除零内中断 · 故障/终止是通常终止进程（无法恢复）
非法操作码内中断 · 终止是终止进程

深挖 4 · 多道程序系统的性能直觉

假设一道程序在 CPU 上计算 60ms、I/O 40ms。单道串行执行两道程序需要 200ms，CPU 利用率 60%。若多道让一道的 I/O 与另一道的 CPU 重叠，理想情况下总时间接近 120ms，CPU 利用率接近 100%。但这是理想值——实际受道数、I/O 设备数量、调度开销影响。408 选择题常给「CPU 利用率」「吞吐量」让你判断多道是否一定更好：道数过多会导致内存不足、换入换出频繁，利用率反而下降。

🌐 多源视角（不同教材的讲法）

  • 【王道《操作系统考研复习指导》】内核态/用户态的判定：看「这条指令会不会影响系统整体或其他进程」。会，就是特权指令；不会，就是普通指令。比死记列表更稳。

提示：系统调用是「自愿陷入」，时钟中断是「被动打断」，缺页是「执行指令时出错」。三者入口不同，但都要进内核。

⚠️ 本章避坑清单

并发 ≠ 并行。单核也能并发，不能并行。
用户态 → 内核态只能靠中断/异常/系统调用；内核态 → 用户态靠特权指令修改 PSW。
系统调用是内核态服务，库函数是用户态代码；printf 不等于系统调用。
缺页是内中断（故障），不是外中断；键盘输入才是外中断。
微内核不是「更小所以更快」，而是更可靠但切换开销更大。
MBR 在磁盘 0 号扇区，先于 OS 运行；它不等于「操作系统内核」。

📝 章内练习（16 题 · 基础 → 提高 → 真题改编）

🟢 第一档 · 基础（4 题）

基础练习 1 · 考点：OS 最基本特征
操作系统最基本的两个特征是：
A. 并发和并行
B. 并发和共享
C. 共享和虚拟
D. 虚拟和异步
解析：选 B。教材把并发与共享视为 OS 最基本的两个特征，二者互为存在条件：没有并发，共享没有意义；没有共享，并发无法实现。并行需要多处理机，不是 OS 的必要特征；虚拟和异步是另外两个特征，但不是「最基本」。
基础练习 2 · 考点：并发与并行
在单处理机系统中，下列活动可以真正并行执行的是：
A. 同一进程的两个线程同时占用 CPU
B. CPU 执行计算与磁盘进行 I/O 传输
C. 两个就绪进程同时运行
D. 中断处理程序与用户进程同时运行
解析：选 B。并行的本质是「同一时刻真正同时」，必须有不同的硬件部件参与。CPU 计算与磁盘 I/O 是不同部件，可以重叠；A、C、D 都要争用同一个 CPU，只能并发（交替），不能并行。
基础练习 3 · 考点：特权指令
下列指令中，属于特权指令的是：
A. 取数指令
B. 加法指令
C. 关中断指令
D. 无条件转移指令
解析：选 C。关中断会影响整个系统的中断响应，必须由内核控制。常见特权指令：关/开中断、置时钟、修改 PSW、切换页表、I/O 指令、停机、加载页表基址。取数、加法、转移都是普通指令，用户态可执行。
基础练习 4 · 考点：OS 功能
下列功能中，不属于操作系统基本功能的是：
A. 进程调度
B. 内存分配与回收
C. 设备分配与缓冲管理
D. 把 C 源程序编译成目标代码
解析：选 D。编译是编译器（如 gcc）的工作，属于语言处理程序，不是 OS 的资源管理功能。OS 的四大管理是处理机、存储器、文件、设备，另加用户接口与扩充机器。

🟡 第二档 · 提高（4 题）

提高练习 5 · 考点：系统调用与库函数
下列关于系统调用与库函数的说法，正确的是：
A. 库函数一定在内核态执行
B. 系统调用一定不涉及用户态
C. 系统调用必然发生用户态与内核态的切换，库函数不一定
D. 库函数不能封装系统调用
解析：选 C。系统调用由内核提供，必须切换内核态；库函数是用户态代码，可能只是纯计算（如 strlen），也可能内部调用系统调用（如 printf 最终可能调用 write）。A、B、D 都说反了。
提高练习 6 · 考点：中断与异常分类
下列事件中，属于内中断（异常）的是：
A. 键盘输入完成
B. 访问的页面不在内存
C. 时钟中断
D. 网卡收到数据包
解析：选 B。缺页是执行访存指令时 CPU 内部产生的异常（故障 fault），处理完会重新执行该指令。A、C、D 都来自 CPU 外部，是外中断。判断技巧：与当前指令执行相关、同步发生的，多为异常；外部设备异步通知的，多为中断。
提高练习 7 · 考点：微内核
微内核结构的主要缺点是：
A. 频繁的用户态/内核态切换与消息传递导致性能开销大
B. 内核代码庞大，可靠性差
C. 无法支持多处理机
D. 不能提供进程通信机制
解析：选 A。微内核把文件系统、驱动等移到用户态，服务之间通过消息传递，路径变长、切换变多，性能是主要代价。B 是宏内核的缺点；C、D 与微内核事实相反——微内核恰恰以进程通信为核心，且易支持多处理机。
提高练习 8 · 考点：多道批处理
与单道批处理相比，多道批处理系统的主要优点是：
A. 交互性更好，响应更快
B. 每个作业的周转时间一定缩短
C. CPU 与 I/O 设备可以重叠工作，资源利用率和吞吐量提高
D. 不再需要作业调度
解析：选 C。多道的核心就是「一道阻塞，另一道顶上」，让 CPU 与 I/O 重叠。A 是分时系统的优点，批处理恰恰缺少交互；B 不一定，多道可能让单个作业等待更久；D 多道更需要作业调度。

🔴 第三档 · 真题改编（8 题 · 题型对标）

真题改编2013 题型练习 9 · 考点：用户态到内核态
下列操作中，不可能在用户态完成的是：
A. 执行算术运算
B. 修改程序状态字 PSW 中的状态位
C. 读取用户自己的变量
D. 执行一条无条件转移指令
解析：选 B。修改 PSW 是特权指令，只能在核态执行；用户态执行会触发异常。A、C、D 都是普通指令。注意：用户态程序可以通过 trap 指令「请求」进入内核，但不能自己改 PSW 强行进入。
真题改编2016 题型练习 10 · 考点：中断处理顺序
中断处理过程中，正确的操作顺序是：
① 保存断点 ② 关中断 ③ 识别中断源 ④ 恢复现场 ⑤ 执行中断服务程序 ⑥ 开中断返回
A. ①②③⑤④⑥
B. ②③①⑤④⑥
C. ②①③⑤④⑥
D. ②①⑤③④⑥
解析：选 C。标准流程：关中断（防止现场被破坏）→ 保存断点（PC、PSW）→ 识别中断源（查中断向量表）→ 执行中断服务程序（其中保存/恢复现场）→ 恢复现场 → 开中断返回。A 先保存断点再关中断，期间可能被新中断打断；B 在保存断点前就去识别中断源，现场还没保住；D 把执行服务程序放到识别中断源之前。
真题改编2018 题型练习 11 · 考点：系统调用参数传递
用户程序向操作系统传递系统调用参数，可以采用的方式不包括：
A. 通过通用寄存器传递
B. 通过栈传递
C. 把参数块的首地址放入寄存器
D. 通过修改中断向量表传递
解析：选 D。常见三种：寄存器、栈、参数块（地址放寄存器）。中断向量表存的是中断服务程序入口，不是参数通道，用户态也改不了它。D 既不是合法方式，也涉及特权操作。
真题改编2015 题型练习 12 · 考点：缺页异常
进程访问的页面不在内存中时，CPU 会产生缺页异常。该异常处理完成后，进程将：
A. 重新执行引发缺页的那条指令
B. 从下一条指令继续执行
C. 被终止
D. 直接转入就绪队列，永不返回
解析：选 A。缺页属于故障（fault），OS 把页面调入内存、更新页表后，返回用户态重新执行刚才那条指令，这次就能正常访问。B 是系统调用/自陷的返回方式；C 是终止类异常；D 描述错误。
真题改编2011 题型练习 13 · 考点：OS 引导
关于主引导记录 MBR，下列说法正确的是：
A. MBR 存放在操作系统内核文件的开头
B. MBR 由操作系统内核在启动后写入
C. MBR 位于磁盘 0 号扇区，包含引导代码、分区表和结束标志
D. MBR 的主要功能是管理文件目录
解析：选 C。MBR 在磁盘 0 号扇区（512B），先于 OS 运行，由引导代码、分区表（最多 4 个主分区）和 55AA 结束标志组成。A、B 把「引导程序」与「内核」混为一谈；D 是文件系统的职责。
真题改编2020 题型练习 14 · 考点：虚拟机
关于第一类虚拟机监视器（Type-1 VMM），下列说法正确的是：
A. 它运行在宿主操作系统之上
B. 它直接运行在硬件之上，客户 OS 运行在其上
C. 它只能运行 Windows 客户机
D. 它不需要特权级压缩
解析：选 B。Type-1（裸金属）VMM 直接跑在硬件上，如 ESXi、Xen；Type-2 才跑在宿主 OS 上（VirtualBox）。客户机类型不限。虚拟机通常需要特权级压缩，让客户 OS 的特权指令陷入 VMM，所以 D 错。
真题改编2022 题型练习 15 · 考点：动态重定位
采用动态运行时装入方式时，下列说法正确的是：
A. 装入时一次性把逻辑地址改为物理地址，运行中不能移动
B. 只适用于单道程序环境
C. 不需要任何硬件支持
D. 地址转换在指令执行时进行，需要重定位寄存器，支持程序在内存中移动
解析：选 D。动态重定位在运行时由硬件（重定位寄存器/MMU）把逻辑地址加上基址得到物理地址，因此程序可以换出、移动，是虚拟内存的基础。A 是静态重定位；B 是绝对装入的局限；C 动态重定位必须靠硬件。
真题改编2019 题型练习 16 · 考点：中断与系统调用综合
下列关于「用户程序调用系统调用」的叙述，错误的是：
A. 用户程序可以直接跳转到内核的系统调用服务程序执行
B. 系统调用通过陷入指令进入内核
C. 系统调用处理过程中可能发生进程阻塞与调度
D. 系统调用返回时要把返回值传回用户程序
解析：选 A。用户程序不能直接跳到内核地址执行——那等于绕过保护机制；必须通过 trap 指令由硬件切换状态并按系统调用号查表进入。B、C、D 都正确：阻塞型系统调用（如读磁盘）会让进程阻塞并触发调度，返回时通过寄存器传返回值。
